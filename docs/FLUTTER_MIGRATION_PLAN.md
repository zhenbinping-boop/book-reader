# 芸窗 Flutter 改进与迁移计划草案

2026 年 11 月 22 日

将芸窗的手机端书架、阅读、笔记和打坐迁到 Flutter，让用户可以在没有可用 WebView 的情况下启动 App、打开本地书和继续阅读。新版首页直接显示书架和续读入口，移除书斋、装扮和功名印展示，成长功能只保留称号。第一轮先在受影响的 Android 10 上迁入旧版书籍、进度和笔记，再跑通离线阅读流程。首个正式版以现有阅读体验和数据完整性为发布条件，离线 OCR、跨书全文检索和系统小组件随后推进。

当前 Android `0.3.0-alpha.7` 的安装下限是 Android 10，启动检查要求常见系统 WebView 达到 140。当前 iOS 工程的最低安装配置是 iOS 15。**Android 10 和 iOS／iPadOS 15 是原型验证目标**，正式支持范围根据 Flutter SDK、PDF 依赖和真机结果确定。[Android SDK 配置](../android/variables.gradle) · [WebView 配置](../capacitor.config.json) · [iOS 工程](../ios/App/App.xcodeproj/project.pbxproj)

## 技术方案

| 模块 | 拟采用的实现 | 原型需要验证 |
| --- | --- | --- |
| 界面与交互 | Flutter 和 Dart。沿用字体和书封，保留打坐的山水与动作素材。首页优先显示续读和书架列表。 | 中文排版、字号放大、深色、减少动态效果，以及低端机上的翻页和动画表现。 |
| TXT | 移植现有编码识别、分章和选区规则，用 Flutter 排版。 | UTF-8 与 GBK 导入、搜索、划词，换字号后继续读同一段。 |
| EPUB | 读取 ZIP、书籍清单和目录，把 XHTML 解析成章节、段落、图片、链接和注音等结构，再用 Flutter 排版。 | EPUB 2 和 3 的目录、中文补字图片和注音、长章、重排及原有标注回跳。用真实书籍确认复杂排版的支持范围。 |
| PDF | 优先验证 PDFium 方案，要求依赖能提供页面渲染、文字提取和文字坐标。界面只缓存可见页及邻近页。 | 在 Android 10 与目标 iOS 设备上验证中文显示、选区坐标、缩放后高亮、长文档内存，以及依赖的许可证和升级维护。 |
| 数据与系统功能 | SQLite 保存书籍目录、进度、标注和会话，原文件保存在应用目录。寻书拟用系统浏览器，下载后通过分享或文件选择导入。 | 重复导入、文件打开和分享、系统终止后的恢复，以及现有书源收藏如何接到新入口。 |

现有阅读器的回读窗、目录、翻页与滚动、书签、笔记导出，以及打坐的暂停与恢复，列入正式切换前的回归清单。[现有阅读能力](../README.md) · [打坐规则](FOCUS.md) · [寻书流程](BOOK_BROWSER.md)

## 首页、打坐与称号

- **首页**。直接显示书架和「继续阅读」。称号以「童生」「秀才」等文字出现在页头。点开可查看累计计入时长，以及到下一称号还需多久。
- **打坐**。保留独立页面、自由专注、读书打坐与专注行迹。自由专注和读书打坐都按实际运行时长计入称号，扣除暂停与休息。提前收功按实际时长结算。
- **称号**。草案沿用现有的称号顺序、晋升门槛和每日上限。阅读与打坐各自记录，汇总称号时按本地自然日合并有效时间段，再应用每日上限。读书打坐中重叠的分钟只计一次。例如打坐 25 分钟，其中 18 分钟同时符合阅读计时条件，这段共计 25 分钟。新版本保存用于去重的计时分段。[现行阅读计时与称号规则](READING_EXPERIENCE.md) · [现行打坐计时规则](FOCUS.md)

## 旧用户迁移

### 保留的数据

- **书库**。保留原书文件、书名、作者、封面、分组、阅读状态和文件身份。先建立旧书 ID 到新书 ID 的映射，再导入关联记录。已有文件指纹随记录保留，旧备份中缺少原文件的条目仍可补回文件。
- **阅读和专注记录**。保留进度、书签、高亮、摘录、笔记、标签、阅读会话与打坐历史。迁入既有阅读经验，保留已获得的称号。旧打坐历史缺少精确的运行与暂停分段，先保留行迹，历史补计方案在核对旧记录后确定。重复恢复按会话 ID 合并。阅读租约在新端重新建立，切换前保存正在进行的打坐状态，并验证恢复或结束后只记一场。[历史打坐记录字段](../src/lib/focusTimer.js)
- **设备设置**。读取旧版单独保存的外观和自定义书源，将这些字段补入迁移格式。现有备份已包含主要阅读数据，导出时勾选「包含原文件」才会带上书籍文件。[现有备份实现](../src/lib/backup.js) · [外观设置](../src/lib/prefs.js) · [自定义书源](../src/lib/bookSources.js)

### 覆盖升级与备份导入

**可覆盖升级的安装版**。先核对包名、签名、版本号和各发行渠道能否沿用同一升级链路。首个 Flutter 版提供本地迁移入口，读取原应用容器和原 WebView 存储源。可通过一张仅处理导出的兼容页面读取旧库，以覆盖跳过过渡版的用户。该入口与 Flutter 的日常启动和阅读分离。当前 Android Alpha 使用固定测试签名，商店正式包的覆盖关系需要在发布前实际验证。[现有签名约定](../README.md#android-alpha-安装包)

**网页／PWA、旧包名或签名不兼容的安装版**。从旧版导出完整备份，在 Flutter 版中导入。Flutter 同时支持旧版 JSON 和新版迁移格式。新版迁移包拟采用数据清单配原文件，按文件逐项读写。针对已卡在 WebView 更新页的用户，先验证一个能同签名覆盖安装的兼容导出包，保留旧数据库和存储源。如果兼容导出页也打不开，已有备份的用户可从备份恢复。其余设备保留原安装和数据，继续确认可提取范围。

**可中断、可重试**。导入先在应用内暂存并校验文件，再按书提交文件和数据库记录。记录已完成的书和待处理项，重启后从检查点继续。重复执行时只处理缺失项，迁移源的一份记录只导入一次。完成后展示逐类数量、待补原文件和待定位标注，保留旧库或备份用于核对。发布出问题时暂停扩大试用，优先修复新版并保持旧数据可读。

### 标注与续读位置

旧 PDF 的高亮位置依赖 PDF.js 的文本项编号，换引擎后按原页、摘录和可用的上下文重新匹配。TXT 和 EPUB 先按原章节与字符偏移定位，再用原文复核。找不到或有多个匹配时保留笔记、摘录及旧位置，标记「待定位」，允许用户重新关联。验收时逐条打开重点标注，确认它跳到正确的文字和页面。[旧 PDF 位置模型](../src/lib/pdfText.js)

## 真机验收

- **设备**。记录实际发生问题的 Android 10 机型、另一台常用 Android 机型、目标最低版本的 iPhone 和一台较新的 iPhone。若发布支持 iPad，再用 iPad 核对布局、文件导入和阅读。
- **样本**。用仓库的 GBK 和 UTF-8 TXT、EPUB 2 和 3、长章节 EPUB 与带文本 PDF，再补带中文字体、多个相同摘录的 PDF、复杂图文 EPUB 和大书库。旧版先建立已知书签、进度、笔记与经验记录，严格核对新版恢复结果。[仓库样本](../samples) · [现有移动验收](../MOBILE_FIXES.md)
- **离线与升级**。分别验证全新安装和覆盖升级。断网启动，打开旧书，检查书签、笔记和阅读位置，再新增一条笔记并重启。故意中断一次迁移并重试，确认记录没有重复、原文件仍可打开，迁移报告能显示缺件。
- **打坐与称号**。验证单独打坐、读书打坐、暂停、休息、提前收功、跨日和重复恢复。核对两种时长重叠时只增加一份称号进度，旧用户升级后保持已获得的称号。
- **性能**。在同一台设备、同一批书上记录冷启动到书架、打开书到正文可读、快速翻页时的表现、峰值内存和大书库迁移耗时。以旧版实测和原型结果定发布门槛。

## 原型完成后确认的事项

- 确定能通过真机验收的 Android 和 iOS／iPadOS 最低版本，以及 Flutter SDK 和 PDF 依赖版本。
- 确定现有 Alpha 到正式发行的签名与升级路径，形成各渠道的用户迁移说明。
- 用旧版备份样本核对阅读与打坐的重叠记录，确定历史打坐时长的补计口径。
- 按 EPUB 和 PDF 原型结果细化工期，明确旧版覆盖升级、手动导入与书籍排版的首发范围。
