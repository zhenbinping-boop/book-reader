# 芸窗 Flutter 实现计划

2026 年 11 月 22 日

手机端采用 Flutter。首页显示书架和续读入口，以文字显示称号。保留打坐，并将实际打坐时长计入称号。书斋、房间装扮和功名印展示从新版移除。旧 Web、PWA 和 Capacitor 工程继续作为已发布版本的维护与迁移来源。产品范围和双端验收目标见[迁移草案](FLUTTER_MIGRATION_PLAN.md)。

## 开发顺序

| 批次 | 实现范围 | 验收 |
| --- | --- | --- |
| 一　旧备份和 TXT 原型 | 在 `flutter_app/` 建立独立的 Flutter 工程。读取现有备份 JSON，显示实际书架与中文书名，从备份原文件打开 TXT，并恢复章节和章内位置。原型先在内存预览选中的备份。 | 用旧版备份结构跑通书架 → 续读。核对章内位置、缺原文件的记录和损坏备份的提示。 |
| 二　本地书库与迁移 | 用 SQLite 存书籍及关联记录，原文件写入应用目录。加入原文件导入、去重、恢复检查点、旧备份导入及新版完整备份。 | 重启后保留数据。重复导入时笔记、会话和书籍不重复。中断后可继续，失败时可恢复旧备份。 |
| 三　三格式阅读 | 完成 TXT 的常见中文编码和保存续读位置。为 EPUB 实现章节解析和 Flutter 排版。验证 PDFium 或同等原生 PDF 组件的渲染、文本坐标与内存。补齐目录、书签、笔记、搜索与回读窗。 | 跑通三格式离线导入、阅读、续读和笔记定位。用长文档、中文字体、图片和重复摘录验证。 |
| 四　打坐与称号 | 接通现有打坐状态、自由专注和读书打坐。阅读时长和打坐时长各自留档，称号按同一天的时间段去重后累计，使用现行称号顺序、门槛和每日上限。 | 暂停、休息、提前收功、锁屏、重启、跨午夜和重复导入都能正确结算。老用户保留已获称号。 |
| 五　升级与发布 | 验证原签名覆盖升级和读取旧存储的本地迁移入口。另提供完整备份导入给网页版与其他安装渠道。验收后分批发布。 | 在受影响的 Android 10 和目标 iOS 设备上安装并断网阅读。验证跳过过渡版、迁移被中断和备份恢复。核实商店签名后再定正式最低支持版本。 |

跨书全文检索、扫描 PDF 离线 OCR、原文回跳和系统小组件在核心阅读与迁移验收后安排。

## 第一批实现

旧版 `src/lib/backup.js` 和 `src/lib/txtText.js` 分别定义备份格式与 TXT 定位规则。它们依赖 JavaScript 运行时，备份的生成和恢复还使用 IndexedDB。Flutter 端复用数据约定和样本，移植读取与分章逻辑，使原型可以从本地文件启动这条阅读链路。[现有备份格式](../src/lib/backup.js) · [TXT 分章规则](../src/lib/txtText.js)

1. 用系统文件选择器打开 `book-reader` 格式的 JSON，验证版本、书籍 ID 和原文件关系。书架显示题名、作者和文件可用状态。
2. 对包含原文件的 UTF-8 与 UTF-16 TXT 验证章节切分、换行规范化和章内偏移。使用旧版 `chapterIndex` 和 `charOffset` 恢复位置。GBK／GB18030 加入中文编码验收后再开放。
3. PDF 和 EPUB 书籍可在原型书架上查看迁移状态。三格式阅读按第三批完成。
4. 以旧版样本作为对照，覆盖含正文、缺正文、书籍 ID 无效和原文件内容损坏的备份。文件选择、签名和安装由原生构建与真机验证。[原型运行与验收说明](../flutter_app/README.md)

## 数据与发布约定

- 旧备份保留在原处。备份显示的是一次读取结果，第二批实现真正写入应用书库的恢复流程。
- 新库写入按书校验原文件与记录，旧书 ID 先映射，再合并进度、高亮、书签和会话。SQLite 与文件写入之间记录检查点，以便恢复中断和安全重试。
- 称号保留既有阅读经验。新事件保存有效运行分段，暂停及休息时间排除，重叠时段只结算一次。旧打坐历史继续可查，历史补计取决于旧数据能否可靠去重。
- 开发原型使用独立安装标识。正式覆盖升级使用经验证的发行标识与签名。iOS 编译与签名在 macOS 构建环境验证，两端的最低系统版本以真实安装和离线阅读结果为准。
